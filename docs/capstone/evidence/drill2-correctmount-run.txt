### Key decision on record — exactly one

**Decision 001: file-based memory inside the repo** (`decisions/decision-001.md`, recorded 2026-09-28, Active). Agent memory is plain files under `.memory/`, committed alongside the code — not a database, not a vector store, not an external mount.

The reasoning, and what it rules out:

- **Why files:** memory that lives next to the code can be diffed against it and cited by commit SHA. The three layers keep the startup read small by separating hot index state from human-maintained rule text from bulky searchable reference material.
- **The evidence behind it:** a Module 2.2 run on 2026-09-26 in this repository compacted one context document from **166,700 → 12,837 tokens**, and the generated summary dropped the unresolved-questions field entirely. That loss is the argument.
- **Vector/embedded DB — deferred, not rejected.** Module 3 needs an MCP-backed retrieval tool with its own evaluation, and the sandbox image has no `python3`, so a Python MCP server requires an image rebuild first.
- **External mounted volume — rejected outright.** Can't be versioned with the code, and a misconfigured mount is the exact scope-leak failure being drilled.
- **Everything in `CLAUDE.md` — rejected.** That file loads every session whether or not it's relevant.
